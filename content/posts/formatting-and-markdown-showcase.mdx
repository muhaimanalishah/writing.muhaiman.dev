# Typography and Hierarchy

Writing on the web should be an inviting, effortless experience. When type is set with intention, ideas flow unobstructed from the writer's mind to the reader's contemplation.

This post serves as a living specimen of every standard Markdown element supported on this website.

## Headings and Structure

Hierarchy gives long-form essays their cadence. Good hierarchy establishes a clear visual rhythm that guides the reader naturally through the text.

### Section Sub-heading (H3)

Sub-headings allow you to break down complex ideas into manageable sections without overwhelming the flow of prose.

#### Minor Heading (H4)

For nuanced subsections or technical breakdowns, fourth-level headings provide subtle emphasis.

##### Fifth-Level Heading (H5)

A quiet delimiter for deeply nested notes or specialized specifications.

###### Sixth-Level Heading (H6)

The subtlest structural marker, often used for meta-commentary or technical headers.

## Paragraphs and Inline Text Styling

Words carry weight not only through their meaning, but through their visual tone. You can emphasize thoughts with **strong bold text** for key assertions, or use *gentle italics* for nuanced reflections. You can also combine them for ***bold and italicized emphasis*** when a point demands unmistakable focus.

When revising thoughts or showing evolution of perspective, you can use ~~strikethrough text~~ to indicate crossed-out thoughts.

Hyperlinks are styled for clear legibility: here is an [internal link to the About page](/about), and here is an [external link to Next.js documentation](https://nextjs.org) with accessible external indicators.

## Lists and Enumerations

Organizing thoughts into structured sequences is essential for tutorials, principles, and structured arguments.

### Unordered Lists

* Typography is the foundation of digital clarity.
* Whitespace is not empty space; it is deliberate structure.
* Fast loading times respect the reader's attention and time.
* Contrast must be comfortable across both bright morning light and late-night reading.

### Ordered Lists

1. Establish your primary thesis in the opening paragraph.
2. Unpack supporting arguments with concise, concrete examples.
3. Address counterarguments with intellectual honesty.
4. Conclude with actionable reflections or open questions.

### Nested Lists

* **Design Principles**
  * Subtraction over addition
    * Remove non-essential decorative borders
    * Eliminate gratuitous animations
  * Ergonomic reading widths
    * Optimal line length: 60 to 75 characters
    * Balanced vertical line-height
* **Technical Principles**
  * Zero runtime JavaScript for static reading
  * Native CSS variable token integration

## Code and Syntax Highlighting

Inline code snippets like `const reader = new Reader()` allow you to reference functions, variables, or terminal commands like `npm run dev` within normal paragraph text.

For multi-line code examples, syntax highlighting with dark and light theme adaptability ensures code remains crisp and legible:

```typescript
interface Essay {
  title: string
  description: string
  date: string
  wordCount: number
}

export function calculateReadingTime(content: string): number {
  const wordsPerMinute = 200
  const words = content.trim().split(/\s+/).length
  return Math.ceil(words / wordsPerMinute)
}
```
